# نصب آسان نود خانگی لوم

یک VPS یا سرور لینوکسی با دسترسی root یا sudo، معماری x64 یا arm64 و systemd
لازم دارید. برای شروع ۲ هسته و ۴ گیگابایت RAM در نظر بگیرید؛ تماس گروهی با
افزایش تعداد افراد منابع بیشتری می‌خواهد.

## ۱. دامنه را وصل کنید

رکورد **A** دامنه یا زیردامنه را روی IPv4 عمومی سرور قرار دهید. برای این نام،
پروکسی CDN را خاموش کنید. اگر رکورد AAAA دارید، IPv6 آن هم باید به همین سرور برسد.
در فایروال پنل VPS، پورت‌های TCP **80 و 443** را باز کنید.

## ۲. این فرمان را اجرا کنید

از طریق SSH وارد سرور شوید و این خط را اجرا کنید:

```bash
bash <(curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/0800x/Loom/main/install.sh)
```

فقط دامنه را تایپ می‌کنید؛ بقیهٔ تنظیمات با کلیدهای **بالا/پایین و Enter** انتخاب می‌شوند.
نیازی به تایپ نام گزینه‌ها نیست. **Esc** نصب را قبل از شروع لغو می‌کند. برای
ترمینال‌های ساده، گزینهٔ `--text` پرسش‌های متنی را فعال می‌کند:

| سؤال | انتخاب‌ها |
| --- | --- |
| منبع دریافت | `official`: منابع اصلی؛ `liara`: میرورهای لیارا؛ `arvan`: داکر آروان و پکیج‌های لیارا |
| دامنه | نام دامنه، بدون `https://` و مسیر |
| ثبت‌نام | `approval`: با تأیید شما؛ `open`: آزاد؛ `closed`: بسته |
| فدراسیون | `trusted`: نودهای مورد تأیید؛ `disabled`: مستقل؛ `open`: نودهای سازگار با احراز هویت معتبر |
| تماس صوتی | `auto`: نصب خودکار TURN؛ `manual`: حفظ سرویس موجود؛ `off`: خاموش |
| تماس تصویری | `yes` یا `no` |
| تماس گروهی | `on`: نصب سرویس رسانه؛ `off`: خاموش؛ `keep`: حفظ تنظیمات قبلی |

خلاصه را بررسی کنید و Enter بزنید. Docker، پایگاه داده، فضای فایل‌ها، HTTPS،
مدیر نود و سرویس‌های تماس انتخاب‌شده نصب و تنظیم می‌شوند. نیازی به ساختن دستی
رمز پایگاه داده یا کپی‌کردن کلید TURN نیست. نصب به دلیل ساخت برنامه چند دقیقه
طول می‌کشد و در پایان مدیر نود باز می‌شود.

راه‌انداز به یک نسخهٔ ثابت از سورس متصل است و هش فایل راه‌انداز و آرشیو کامل
سورس را قبل از اجرای نصب با دسترسی مدیریتی بررسی می‌کند. فرمان اولیه را از
آدرس رسمی پروژه بگیرید. اجرای مجدد، هویت نود، داده‌ها و رمزهای معتبر موجود را
حفظ می‌کند. سرویس وب یا TURN متعلق به برنامهٔ دیگری خودکار جایگزین نمی‌شود.

## نصب روی سرور ایران

اولین منو منبع دانلود را می‌پرسد: **منابع اصلی، لیارا، یا داکر آروان همراه پکیج‌های لیارا**.
انتخاب برای راه‌اندازی مجدد و آپدیت سورس ذخیره می‌شود. اجرای غیرتعاملی با
`--downloads liara` یا `--downloads arvan` هم ممکن است.

این انتخاب شامل ایمیج‌های Docker Hub، ماژول‌های Go، پکیج‌های npm، مخازن Alpine
داخل کانتینرها و بسته‌های میزبان Ubuntu amd64 و Debian است. مخازن توزیع‌های دیگر
و مخزن اختصاصی نصب Docker Engine همچنان همان تنظیمات میزبان را استفاده می‌کنند.
برای Ubuntu ARM64 باید میرور مناسب Ubuntu Ports را جداگانه روی میزبان تنظیم کنید.

تنظیمات Docker و فایل مخازن کل سرور بازنویسی نمی‌شوند؛ برای تغییر میرور Docker
نیازی به ری‌استارت آن نیست. امضای بسته‌ها، هش سورس، digestهای ثابت ایمیج، TLS و
بررسی صحت ماژول‌های Go فعال می‌مانند. ایمیج‌های دارای تگ قابل‌تغییر از میرور
انتخاب‌شده دریافت می‌شوند؛ این انتخاب به معنی اعتماد به همان ارائه‌دهنده برای آن تگ است.

**این حالت نصب کاملاً آفلاین نیست.** دریافت سورس GitHub، وابستگی‌های کش‌نشده،
بررسی checksum در صورت نیاز و صدور گواهی HTTPS ممکن است به اینترنت خارجی نیاز
داشته باشند. خطای میرور باعث توقف می‌شود؛ منبع بعدی را خودتان در نصب انتخاب کنید.
جزئیات و پیوند مستندات رسمی ارائه‌دهندگان در [راهنمای انگلیسی](node-setup.md#installing-from-iran) آمده است.

## توزیع‌های لینوکس

برای Ubuntu، Debian، Fedora، CentOS Stream، RHEL، Rocky Linux، AlmaLinux،
Arch/Manjaro و openSUSE/SLES مسیر نصب بسته‌ها وجود دارد. نسخهٔ تحت پشتیبانی و
مخازن سالم لازم است؛ پشتیبانی از همهٔ نسخه‌های قدیمی یا CentOS Linux منقضی‌شده
وجود ندارد. Arch هنگام نصب پیش‌نیازها ارتقای کامل سیستم انجام می‌دهد.
مخازن یا اشتراک لازم در RHEL باید از قبل قابل استفاده باشند.

آزمون انتخاب بسته‌ها با فرمان‌های شبیه‌سازی‌شده انجام می‌شود؛ نصب کامل واقعی
روی تک‌تک توزیع‌ها هنوز تأیید نشده است. توضیح دقیق‌تر در
[راهنمای انگلیسی](node-setup.md#linux-distributions) آمده است.

## ۳. پورت‌های تماس را باز کنید

| قابلیت | پورت ورودی عمومی |
| --- | --- |
| سایت و پیام‌رسانی | TCP 80 و 443 |
| تماس صوتی و تصویری | TCP و UDP 3478، و UDP 49160–49200 |
| رسانهٔ تماس گروهی | TCP 7881، و UDP 50000–50100 |

نصب‌کننده قوانین UFW یا firewalld فعال را برای قابلیت‌های انتخاب‌شده تنظیم
می‌کند. فایروال پنل شرکت VPS، قوانین سفارشی nftables/iptables و انتقال پورت
روتر را خودتان تنظیم کنید. پورت 7880 و سرویس‌های داخلی نباید عمومی شوند.

## ۴. به نود وصل شوید

صفحهٔ `https://YOUR_DOMAIN` را از شبکه‌ای دیگر باز کنید و نود را با لینک یا QR
در لوم اضافه کنید. اگر ثبت‌نام را روی `approval` گذاشته‌اید، درخواست حساب را
در **Registrations** تأیید کنید. سپس با دو دستگاه روی دو شبکهٔ متفاوت، پیام و
تماس را آزمایش کنید. بالا آمدن سرویس به‌تنهایی ثابت نمی‌کند صدا و تصویر از
فایروال شرکت میزبان عبور می‌کنند.

برای باز کردن دوبارهٔ مدیر نود:

```bash
loom
```

کلیدهای جهت برای حرکت، Tab برای تغییر بخش، Enter برای انتخاب، `?` برای راهنما
و `q` برای خروج هستند. خروج از مدیر نود، سرور را خاموش نمی‌کند.

برای تغییر انتخاب‌ها و باز کردن دوبارهٔ ویزارد:

```bash
loom setup
```

در فدراسیون `trusted`، نودهای دیگر را از صفحهٔ **Federation** بررسی و تأیید
کنید. گروه متنی MLS به سرویس تماس گروهی نیاز ندارد. آپدیت‌ها هنگام اجرای مدیر
نود خودکار بررسی می‌شوند؛ نصب آپدیت از **Updates → Install update** با انتخاب
شما و برای نسخهٔ تأییدشده انجام می‌شود.

برای پیش‌نمایش بدون تغییر سرویس‌ها، فایل `install.sh` را دانلود کنید و
`bash install.sh --plan` بزنید. اگر نصب به دلیل DNS، HTTPS، پورت اشغال یا هش
نامعتبر متوقف شد، خطا را برطرف کنید؛ بررسی امنیتی را حذف نکنید.

از هویت نود، پایگاه داده، فایل‌ها و تنظیمات نسخهٔ پشتیبان بگیرید. فایل `.env`،
کلیدهای رسانه، توکن و اطلاعات بازیابی را منتشر نکنید.

[راهنمای کامل مدیر نود](node-manager.md) · [استقرار پیشرفته](../services/loom_server/deploy/README.md) · [آپدیت و انتقال آفلاین](loom-node-update-and-offline.md)

برای تشخیص خطای شروع سرور، `sudo loom doctor` را اجرا کنید. این فرمان سرویس‌ها
و رمزها را تغییر نمی‌دهد و اطلاعات محرمانه را چاپ نمی‌کند. در نسخهٔ قدیمیِ
مدیر نود می‌توانید فایل نصب جدید را از آدرس رسمی بگیرید و
`bash install.sh --diagnose` اجرا کنید.

اگر volumeهای قبلی وجود دارند ولی `.env` ندارید، تنظیمات اصلی را از پشتیبان
برگردانید. رمز جدید در `.env`، رمز ذخیره‌شده داخل PostgreSQL قبلی را تغییر
نمی‌دهد. حذف volume یا ساخت هویت تازه راه‌حل این خطا نیست.

اگر دریافت ماژول با `403 Forbidden` متوقف شد، مشکل دسترسی خروجی سرور به منبع وابستگی است؛ پاک‌کردن داده‌ها کمکی نمی‌کند. در نصب دوباره، منبع لیارا یا آروان را انتخاب کنید. بررسی `go.sum` و پایگاه عمومی checksum فعال می‌ماند. اگر میرور هم مسدود باشد، دسترسی را اصلاح کنید.

## HTTPS بدون دامنه و راه‌اندازی TURN

در منوی HTTPS، حالت **Local** را انتخاب کنید و نام میزبان محلی یا IPv4 سرور را بدهید.
گواهی روی همان سرور، بدون تماس با مرجع صدور، ساخته می‌شود. فایل عمومی
`/opt/loom-node/deploy/tls-local/fullchain.pem` را از مسیر مطمئن به موبایل منتقل کنید؛
**کلید `privkey.pem` را منتقل نکنید.** در صفحهٔ انتخاب سرور Loom، گزینهٔ واردکردن
گواهی محلی را بزنید، اثر انگشت SHA256 را با خروجی سرور مقایسه کنید، اعتماد را
تأیید و برنامه را دوباره باز کنید. نسخه‌های قدیمی برنامه این گزینه را ندارند.
مدیریت و حذف اعتماد هم در همان صفحه است و پس از حذف، برنامه باید دوباره باز شود.

این حالت جای خطای گواهی عمومی را خودکار نمی‌گیرد و بررسی TLS و هویت امضاشدهٔ
نود را خاموش نمی‌کند. پخش‌کننده‌ها و اجزای تماس بومی ممکن است به اعتماد در سطح
سیستم‌عامل هم نیاز داشته باشند؛ رفتار آن‌ها باید روی دستگاه واقعی بررسی شود.
برای شبکهٔ مستقل، فدراسیون را خاموش بگذارید. تنظیم فعلی تماس گروهی به IPv4
عمومی نیاز دارد؛ گروه متنی MLS به سرویس تماس گروهی وابسته نیست.

برای TURN، تماس صوتی را روی **auto** بگذارید. نصب سرویس، تنظیم دامنه، ساخت
secret و اتصال تنظیمات تماس به نود خودکار انجام می‌شود. اجرای دوباره secret
معتبر قبلی را حفظ می‌کند. بعداً هم در **Calls → Set up TURN automatically**
همین کار بدون ساخت مجدد نود انجام می‌شود. فایروال پنل دیتاسنتر و NAT باید
پورت‌های اعلام‌شده را عبور دهند؛ سرویس TURN نامرتبط تصاحب نمی‌شود.

در حالت میرور ایران، نصب تازهٔ Docker روی Ubuntu و Debian 13+ از بسته‌های
امضاشدهٔ توزیع استفاده می‌کند و برای کلید Docker به download.docker.com درخواست
نمی‌زند. انتخاب آروان، میرور بسته‌های Ubuntu و Alpine آروان را هم فعال می‌کند.

## تغییر مستقل میرور Go

در هر دو حالت لیارا و آروان، منبع پیش‌فرض ماژول‌های Go لیارا است. برای
تغییر فقط Go، نصاب تأییدشده را با این گزینه اجرا کنید:

```bash
bash install.sh --downloads liara --go-mirror runflare
```

گزینه‌های مجاز `profile`، `official`، `liara`، `runflare`، `parspack` و `goproxy-cn`
هستند. انتخاب ذخیره می‌شود و هم برای ساخت Node Manager و هم MinIO استفاده
می‌شود؛ تنظیمات عمومی Go و منابع Docker/npm/APT تغییر نمی‌کنند.
رانفلر آدرس `https://mirror-go.runflare.com` و Goproxy.cn آدرس
`https://goproxy.cn` را مستند کرده‌اند. دسترسی از هر سرور باید جدا بررسی شود.

مرحلهٔ دانلود ماژول‌های MinIO از کامپایل جدا نمایش داده می‌شود و سقف ده دقیقه
دارد. کش BuildKit، ماژول‌های تأییدشده و پکیج‌های کامپایل‌شده را پس از قطع ساخت
نگه می‌دارد؛ برای رفع این مشکل کش Docker را پاک نکنید. کنترل checksum و TLS
فعال می‌ماند و خطا باعث تغییر خودکار میرور نمی‌شود. کامپایل نام پکیج‌ها را
نمایش می‌دهد و دریافت ماژول جدید در آن غیرفعال است. روی سرور ضعیف، خود
کامپایل هم می‌تواند زمان‌بر باشد.

[مستندات رانفلر](https://runflare.com/mirrors/go-mirror/) ·
[مستندات Goproxy.cn](https://goproxy.cn/)

## پارس‌پک و نسخهٔ پایهٔ Alpine

برای ماژول‌های Go پارس‌پک، گزینهٔ `--go-mirror parspack` به آدرس رسمی
`https://mirror.abrha.net/repository/go/` وصل می‌شود. کنترل checksum روشن
می‌ماند؛ نمونهٔ `GOSUMDB=off` در راهنمای ارائه‌دهنده اعمال نمی‌شود.

سازندهٔ TUI و MinIO از Go 1.25.14 با Alpine 3.23 و digest ثابت استفاده
می‌کنند. تگ شناور `-alpine` دیگر باعث مهاجرت خودکار به نسخه‌ای نمی‌شود که
میرور APK هنوز ندارد. امضای پکیج‌ها بررسی می‌شود و مخازن دو نسخهٔ Alpine
با هم ترکیب نمی‌شوند.

[راهنمای Go پارس‌پک](https://docs.parspack.com/reference/mirror/golang/) ·
[فهرست میرورهای NuGet](https://github.com/VahidN/nuget-net-melli-mirrors)

فهرست دوم مخصوص NuGet/.NET است؛ آدرس‌های آن جایگزین Go یا APK نیستند.
نصاب لینوکس تنظیمات سراسری NuGet و گزینه‌های audit آن را تغییر نمی‌دهد.
